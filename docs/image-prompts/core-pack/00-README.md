# 凡人修仙模拟器｜像素美术首发包 v4.0 Core

> **首发只需要 55 张图。** 这与当前游戏运行时的 29 个场景和 10 个动作图标完全对齐，并补齐 4 个本心、6 个年度重心和 6 个结局。

## **一、数量**

| 资产 | 数量 |
|---|---:|
| 场景母图 | 29 |
| 本心开场 | 4 |
| 年度重心 | 6 |
| 结局 | 6 |
| 动作图标 | 10 |
| **合计** | **55** |

## **二、先做什么**

1. 先生成 `batches/01-core-scenes.md` 的 29 张场景母图。
2. 再生成 `batches/02-openings-focus-endings.md` 的 16 张关键氛围图。
3. 最后生成 `batches/03-action-icons.md` 的 10 个动作图标。
4. 将 PNG 按 `OUTPUT-PATHS.txt` 放入 `public/game/` 对应目录，同名覆盖占位图。
5. 运行测试、构建，并在手机宽度检查主体、文字承托区和动作图标可读性。

## **三、为什么能从 515 压到 55**

- 不再为 231 个基础选项和 108 个命运选项分别画结果图。
- 一个场景母图负责地点、人物、光线和情绪。
- 动作图标负责“谈、战、行、修、买、救、疗、险、拒、察”的语义。
- UI 状态层负责显示选择后的关系、代价和结果。
- 96 个基础事件和 54 个命运幕次按 29 个场景语义归并，避免同一地点反复出图。

| `batches/03-action-icons.md` | 10 张动作图标完整提示词 |

## **五、统一规格**

- 场景：1536×864，16:9 PNG。
- 图标：1024×1024 PNG。
- 场景关键主体位于中央 4:3 安全区。
- 底部 22% 保留文字承托区。
- 统一 16-bit / 32-bit JRPG 像素密度、深色描边、3 到 5 阶明暗和克制旧金高光。
- 参考成熟作品的高层设计方法，不复制任何可识别资产。

## **六、决策边界**

先用这 55 张验证“场景母图 + 动作图标 + 状态层”是否足够有趣、可读、耐看。未来只有在真实游玩数据证明某类场景重复感明显时，才另开新版本补充局部变体，不在当前仓库继续堆积全量提示词。
