# fanren-wiki 玩法大改造实施蓝图

> 目标：从“点击随机修仙事件”升级为“可重复体验、可解释、可对照的修仙人生模拟”。
>
> 设计原则：学习人生模拟的状态机与反馈结构，不照搬 1in8b 的现代人生内容，也不把灵根做成命运上限。
>
> 当前基线：18 条命运线、八轴叙事、选择记忆与组合结局已可运行；61 项测试、生产构建、浏览器验收均通过。

## 一、启动判断

### 结论

**可以着手改造。**

但不应直接推倒 `app/game/play/page.tsx` 重写，也不应一次性同时加入阶段时钟、关系网络、乱星海、三生镜和全部新 UI。

正确方式是：

> **先搭一条完整的“可活完一生”的纵向切片，再逐步替换旧循环。**

### 当前唯一工程风险

`fanren-wiki` 当前仓库没有任何 Git 提交，所有文件均未跟踪。

这意味着：

- 无法用正常 Git diff 对比大改造前后的完整基线；
- 出问题时不能 `git reset` 到上一版；
- 后续文件审查只能依靠文件清单和局部 diff。

本轮不自动 commit/push。建议在大改代码前，由用户确认是否建立一次基线提交；若仍不提交，则先保留当前文件快照。

## 二、目标体验

### 一句话

> 每一世都在回答：你会为了什么修道，又会为了什么放弃修道？

### 单局体验目标

- 单局时长：10–20 分钟；
- 单局阶段：约 12–20 个阶段；
- 单局关键选择：20–35 次；
- 每局至少出现 1 次不可逆代价；
- 每局至少出现 1 次旧选择回响；
- 每局抽取 3–4 条命运线，而不是全部开放；
- 结局必须能解释“你这一生像什么”。

### 玩家每一阶段的决策

```text
本阶段把时间花在哪里？
→ 推进若干年
→ 自动结算修为、寿元、伤势、资源、关系
→ 处理一个生活事件或命运线事件
→ 留下选择记忆
→ 决定是否远行、突破、归乡或闭关
```

## 三、核心状态机

```text
灵根抽取（保留现状）
→ 本心一问
→ 命格谶语
→ 入世
→ 阶段循环
   → 选择阶段重心
   → 结算时间与状态
   → 触发事件
   → 选择与后果
   → 写入关系/因果/时间线
   → 检查突破或死亡
→ 命盘审判
→ 留下执念
→ 下一世继承有限刻印
→ 三生镜
```

### 一局内部的主状态

1. 生命状态：年龄、剩余寿元、伤势、疾病、死亡。
2. 修炼状态：境界、修为、突破经验、灵根影响。
3. 资源状态：灵石、丹药、法器、阵法。
4. 关系状态：师门、道友、仇敌、凡人亲族。
5. 叙事状态：八轴、标签、伤疤、称号、选择记忆。
6. 命运状态：命格谶语、本心、命运线、执念、因果刻印。
7. 世界状态：时代、宗门、地区、远行与归来。

## 四、时间模型改造

### 当前问题

现有 `lifespan` 更像“还能活多少年”，`lifespanMax` 是当前境界寿命上限；而日志中的“寿元第 X 年”并不是真正的年龄。

人生模拟需要区分：

- **年龄**：角色活了多少年；
- **剩余寿元**：距离死亡还有多少年；
- **境界寿命上限**：当前境界允许的最高年龄；
- **阶段耗时**：本阶段推进多少年。

### 建议模型

```ts
interface GameState {
  age: number;
  remainingLifespan: number;
  lifespanLimit: number;
  stage: number;
  stageStartedAge: number;
}
```

为减少一次性破坏，可以在迁移期保留旧字段并在 selector 中转换。

### 阶段长度

建议按境界配置：

| 境界 | 单阶段年数 |
|---|---:|
| 炼气 | 5 年 |
| 筑基 | 10 年 |
| 结丹 | 20 年 |
| 元婴 | 40 年 |
| 化神 | 80 年 |

阶段长度放在配置中，不写死在页面。

### 时间推进顺序

必须固定：

```text
1. 年龄增加
2. 剩余寿元减少
3. 阶段重心收益结算
4. 修为与突破状态结算
5. 伤势/疾病结算
6. 灵石与资源结算
7. 关系漂移结算
8. 世界/宗门时局推进
9. 更新事件冷却
10. 生成候选事件
11. 检查死亡
```

否则会出现“死亡后加修为”“结局后关系才更新”等状态错误。

## 五、阶段重心

首版六类：

| 重心 | 主要收益 | 主要代价 | 倾向事件 |
|---|---|---|---|
| 苦修 | 修为、突破经验 | 关系疏远、错过时局 | 闭关、心魔、瓶颈 |
| 游历 | 机缘、见识、命运线推进 | 风险、寿元 | 秘境、旧人、奇遇 |
| 炼丹/阵法 | 资源、专业能力 | 灵石、时间 | 丹毒、阵图、交易 |
| 宗门事务 | 地位、人脉 | 修炼时间减少 | 清洗、战争、执法 |
| 人情往来 | 关系、信任、牵挂 | 修炼效率下降 | 故乡、师门、道友 |
| 养伤/隐居 | 恢复伤势、降低仇怨 | 错过机缘 | 隐居、追兵、静修 |

### 设计原则

阶段重心的核心不是固定加成，而是：

> **改变下一阶段的事件池与风险结构。**

## 六、灵根重构

### 目标定位

> 灵根决定起点和风格，不决定命运上限。

### 数值建议

| 灵根 | 修炼效率 | 风格 |
|---|---:|---|
| 天灵根 | 1.3× | 正统、资源主动靠拢、被寄予厚望 |
| 双灵根 | 1.15× | 兼容、转修、结盟、游历 |
| 三灵根 | 1.0× | 自由、散修、海外探索 |
| 伪灵根 | 0.85× | 慢，但偏门、杂学、禁术、残篇、高变量 |

灵根效率只影响自然修炼，不影响：

- 机缘；
- 顿悟；
- 秘境传承；
- 魔道禁术；
- 飞升资格；
- 是否可去乱星海。

### 灵根画像

除倍率外，增加数据驱动标签：

```ts
interface SpiritRootProfile {
  cultivationMult: number;
  tags: Array<"orthodox" | "adaptive" | "free" | "heterodox">;
  eventBias: Record<string, number>;
  riskBias: number;
  reputationBias: number;
}
```

## 七、关系系统

### 首批关系类型

- 师门：师尊、同门；
- 道友：盟友、竞争者、旧友；
- 仇敌：追杀者、背叛者；
- 凡人亲族：父母、兄弟、故乡故人。

### 关系数据

```ts
interface Relation {
  id: string;
  name: string;
  kind: "master" | "peer" | "rival" | "kin" | "companion" | "disciple";
  affinity: number;
  trust: number;
  status: "active" | "estranged" | "dead" | "lost";
  lastInteractionStage: number;
  tags: string[];
}
```

### 关系参与

- 关系强度决定事件出现；
- 关系变化进入时间线；
- 死亡时生成“送最后一程的人”；
- 命运线可绑定具体人物，而不是抽象标签。

## 八、事件池与触发条件

### 事件元数据

```ts
interface EventCondition {
  minAge?: number;
  maxAge?: number;
  minRealm?: RealmSlug;
  minStage?: number;
  axes?: Partial<Record<NarrativeAxis, { min?: number; max?: number }>>;
  tagsAny?: string[];
  tagsAll?: string[];
  scarsAny?: string[];
  relations?: Array<{
    kind: Relation["kind"];
    minAffinity?: number;
    status?: Relation["status"];
  }>;
  focusAny?: FocusId[];
  flags?: Record<string, boolean | number>;
}

interface EventMeta {
  condition?: EventCondition;
  weight?: number;
  once?: boolean;
  cooldownStages?: number;
  priority?: number;
}
```

### 候选池流程

```text
全部事件
→ 境界过滤
→ 年龄/阶段过滤
→ 叙事轴过滤
→ 标签/伤疤过滤
→ 关系过滤
→ 阶段重心过滤
→ 世界标记过滤
→ 排除冷却和一次性事件
→ 强制事件优先
→ 普通事件按权重随机
```

### 两层事件

- **人生事件**：亲情、疾病、师门、钱财、关系、时局；
- **命运线事件**：三段因果，按轮次插入。

### 每阶段事件预算

- 1 个主事件；
- 0–1 个关系事件；
- 命运线满足条件时替换主事件；
- 每阶段最多 2 个选择界面，避免阅读过载。

## 九、冒险与平淡双路线

### 乱星海不是地图，是“远行链”

```text
决定远行
→ 选择出海方式
→ 3–5 个航行节点
→ 海外遭遇
→ 归返或失踪
→ 世界变化
```

### 三层选择

1. 为什么出海：寻药、避仇、追人、求机缘、被卷入；
2. 怎么出海：商船、散修船队、独舟、跟随仇人、神秘引路；
3. 愿意付什么代价：积蓄、法器、承诺、同行拖累、隐瞒目的。

### 风险表达

不显示精确成功率，只显示风险类型：

- 九死一生；
- 来历不明；
- 有人同行，但目的不明；
- 归期难料；
- 可能牵动旧因果。

### 平淡路线

必须可完成、可自豪：

- 守山；
- 收徒；
- 经营地方声望；
- 照顾亲族；
- 研究杂学；
- 留在小地方改变许多人。

结局不能把“未飞升”自动等同于失败。

## 十、命格谶语与轮回

### 本心

开局选择：

- 长生；
- 复仇；
- 守护；
- 自在。

本心不直接加数值，影响结局判词与部分事件选项。

### 命格谶语

每局抽一句待验证的命：

- 顺命；
- 逆命；
- 证命；
- 问命。

命格只改变事件、关系和结局，不加战斗数值。

### 执念

死亡时选择一个最放不下的事：

- 没救下的人；
- 没说完的话；
- 没杀掉的仇人；
- 没走完的道；
- 没回去的故乡。

执念生成下一世的隐藏命劫或命运线。

### 因果刻印

每局最多保留 3 个：

- 一个人；
- 一个地点；
- 一条道统/传闻。

避免世界状态无限增长。

### 三生镜

三局后总结行为模式，不给高分，只照见：

- 总在什么之间选择；
- 总保护谁；
- 总辜负谁；
- 哪条命运线一直回避。

## 十一、结局结构

### 命盘

结局至少包含：

- 本心；
- 命格判定；
- 最终境界；
- 死亡/飞升方式；
- 三段主要关系；
- 两条命运线；
- 一条未完成因果；
- 最大成就；
- 最大代价；
- 四组修仙纹理；
- 一句命运判词；
- 唯一签名。

### 修仙纹理

建议四轴：

- 守道 / 逐势；
- 独行 / 结缘；
- 慈悲 / 杀伐；
- 人间 / 天门。

由现有八轴映射，不新建平行状态。

## 十三、随机与可复现

### 必须使用种子随机

当前多个模块直接使用 `Math.random()`，会导致：

- 测试不稳定；
- “同命重开”无法复现；
- 问题难以排查；
- 随机体验不可审计。

建议：

```text
runSeed
+ turn / stage
+ 事件 id
→ 生成独立随机流
```

玩家看到的仍然是未知结果，但系统内部可复现。

## 十四、纵向切片范围

第一轮不要做完整大版本，只做一条可玩闭环：

### M1.1 核心引擎

- 年龄与阶段；
- 阶段重心；
- 固定结算顺序；
- 种子随机；
- 时间线记录；
- 现有命运线继续可用。

### M1.2 单局 UI

- 阶段重心选择；
- 推进阶段；
- 事件选择；
- 结局命盘；
- 本局时间线。

### M1.3 内容与关系

- 4 类关系；
- 至少 12 个带条件的人生事件；
- 3–4 条命运线抽样；
- 一条平淡路线；
- 一次远行机会。

### M1.4 轮回层

- 本心；
- 命格谶语；
- 执念；
- 最近三局记录；
- 三生镜雏形。

### M1 暂不做

- 完整乱星海大地图；
- 多人或联网；
- 复杂宗门经营；
- 全部 18 条命运线合流；
- 付费系统；
- 完整美术换皮。

## 十五、验收标准

### 功能

- 可以从灵根抽取开始，完整走完一生；
- 年龄单调递增，寿元与死亡判定正确；
- 每阶段只结算一次；
- 阶段重心实际改变事件池；
- 灵根不封锁任何境界或区域；
- 至少一条命运线可落定或断裂；
- 结局能展示本心、命格、关系、命运线和判词。

### 随机与存档

- 同 seed + 同选择可复现；
- 不同选择产生不同时间线；
- 刷新后本局不丢失；
- 历史存档带版本号；
- 旧版存档失败时安全降级，不覆盖原文。

### 平衡

自动模拟至少 1000 局，检查：

- 无负年龄、负寿元、重复死亡；
- 无空结局；
- 无单条结局超过 40%；
- 四条灵根都能进入高境界；
- 每条命运线至少触发一次；
- 平淡路线与冒险路线都能形成有效结局。

### 体验

- 单局 10–20 分钟；
- 每局至少一次明确回响；
- 每局至少一次不可逆选择；
- 每局至少一段关系变化；
- 过程中不直接展示命运线阶段进度；
- 结局集中揭示因果与判词。

## 十六、实施顺序

```text
0. 确认基线（建议，但未经用户要求不 commit）
1. 年龄/阶段/结算核心
2. 种子随机与事件池
3. 阶段重心与 UI
4. 关系系统
5. 本心/命格/执念
6. 乱星海远行与平淡路线
7. 时间线/存档/命盘
8. 三生镜
9. 1000 局模拟与浏览器验收
```

## 十七、当前直接结论

- 可以开始，但应做纵向切片，不应一次推倒全部页面。
- 第一轮最高优先级是：**年龄与阶段时钟、阶段重心、固定结算顺序、事件池条件**。
- 关系、本心、命格、执念要围绕这条核心循环接入。
- 乱星海与平淡路线必须同时成立，不能把冒险做成唯一正解。
- 灵根必须保留差异，但取消高境界与区域准入限制。
- 不自动 commit/push；每轮代码完成后先展示文件清单与 diff 摘要。
