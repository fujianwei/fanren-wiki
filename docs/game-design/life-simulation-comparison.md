# 1in8b 正式网站 20 局 vs fanren-wiki 玩法对比矩阵

> 对比对象：`https://1in8b.life` 正式网站 20 局样本；本地 `fanren-wiki` 凡人修仙模拟器。
>
> 历史基线：本轮代码改造前，`fanren-wiki` 只有灵根抽取、境界成长、单次事件、闭关、战斗、灵市和简单结局。`types/game.ts` 已定义叙事轴、命运线、选择记忆和结局总结类型，但 `GameProvider` 未初始化这些字段，`fate-threads.json` 未进入运行时。
>
> 当前状态：已完成第一轮命运线重构。下表的“本次后”列以当前工作区代码为准。

## **一、总览**

## **二、逐项差异与重构判断**

### **1. 出生仪式**

**1in8b**：随机出生 + 出生登记 + 家庭统计 + 同秒同伴，核心是“你无法选择出生”。

**fanren-wiki**：蓝色火焰抽取灵根，核心是“你终于有了修仙资质”。

**判断**：两者都应该保留。灵根抽取是修仙题材的仪式感，真实出生统计不是当前产品的必要目标。

**本次处理**：严格保留出生火焰、出生文案和现有修仙视觉，不在灵根抽取前插入现代人口面板。

### **2. 时间与节奏**

**1in8b**：年为单位，年度重心与关键抉择交错。

**fanren-wiki**：事件为单位，寿元是资源，不是时钟。

**差异**：当前玩家可以无限点击“寻求机缘”直到寿元耗尽，缺少“这一年怎么过”的中间层。

**需要重构**：

- 增加年度/阶段 tick；
- 每 tick 自动结算年龄、修炼、灵石、关系、健康；
- 每若干年允许选择本阶段重心；
- 事件作为 tick 中触发的例外，而不是唯一行动。

**优先级**：P0。

### **3. 命运线落地**

**1in8b**：隐式因果链，通常不会明确告诉玩家“这是第几段命运线”。

**fanren-wiki 改造前**：`fate-threads.json` 存在但完全不参与运行时。

**fanren-wiki 本次后**：

- 18 条命运线全部加载；
- 每条三阶段；
- 命运线阶段转换成现有 `GameEvent`；
- 新命运线与普通事件交替出现；
- 选择写入八轴、标签、记忆和命运线状态；
- 第三阶段自动 resolve/break；
- 结局总结展示已落定与未落定命运线。

**差异**：1in8b 更隐式，fanren-wiki 当前 UI 明确显示“命运线 · 第 X/3 段”。

**判断**：当前显式展示适合修仙游戏的可读性，但后续应降低提示强度，让玩家通过人物、地点和旧物识别回响。

### **4. 关系系统**

**1in8b**：关系是事件结果与死亡总结的核心结构。

**fanren-wiki**：目前只有命运线标签和记忆，没有父母、伴侣、子女、师门、道友的结构化状态。

**需要重构**：

- 建 `relations` 状态：类型、姓名、关系强度、状态、最后互动年龄；
- 事件效果支持 `relation_delta`；
- 死亡总结计算“送最后一程的人”；
- 命运线可以与关系绑定，而不只是标签。

**优先级**：P0。

### **5. 年度重心**

**1in8b**：重心是慢变量，决定长期属性和事件概率。

**fanren-wiki**：当前只能通过寻求机缘/闭关/历练等主动行动推动成长。

**需要重构**：

- 每 1–5 年选择一次阶段重心；
- 修仙语义示例：苦修、游历、炼丹、阵法、宗门事务、人情往来、养伤；
- 重心驱动自动事件权重，而非直接加固定数值。

**优先级**：P0。

### **6. 选择层与状态层**

**1in8b**：事件是表层，状态与关系是底层。

**fanren-wiki 改造前**：事件是唯一玩法，状态只用于突破和战斗。

**fanren-wiki 本次后**：已有叙事轴与记忆，但还缺少“选择 → 状态 → 后续事件池”的完整反馈。

**需要重构**：

- 事件筛选项加入叙事轴阈值、伤疤、称号、关系、命运线阶段；
- 同一事件在不同轴状态下显示不同文案与选项；
- 终局不只读取 `endingType`，还要读取主轴和命运线。

**优先级**：P1。

### **7. 组合终局**

**1in8b**：死因只是最后一层，真正被记住的是纹理和回首。

**fanren-wiki**：已有六类结束原因。

**本次后**：组合为“修士原型 × 结束原因 + 主轴 + 命运线 + 关键记忆 + 墓志铭”。

**剩余差异**：

- 还缺原生“人生纹理”可视化；
- 还缺死亡前的最后一段关系/财产/称号收束；
- 还没有跨局收集的结局谱系。

**优先级**：P1。

### **8. 总结展示**

**1in8b**：先事实、后纹理、再回首，层级清楚。

**fanren-wiki 本次后**：已有组合结局标题、主轴标签、命运线清单、关键记忆与墓志铭。

**剩余差异**：

- 缺完整事件时间线；
- 缺“最高光的一年/最幸福的一年”；
- 缺关系、财产、称号的结构化摘要；
- 缺分享卡或可导出的本局结局卡。

**优先级**：P1。

### **9. 重玩与留存**

**1in8b**：随机出生、前世纪录、同秒同伴、每日主题、分享卡、追思馆。

**fanren-wiki**：灵根重抽是天然重玩入口，但单局选择记忆目前不能跨刷新保存。

**需要重构**：

- 本局事件时间线持久化；
- 最近 N 局的结局档案；
- 命运线图鉴：已落定/断裂/未触发；
- 主轴称号收集；
- 分享卡与“再来一世”入口。

**优先级**：P1–P2。

## **三、本轮已完成的代码重构**

### **数据与运行逻辑**

- 接入 `content/game/fate-threads.json` 的 18 条命运线；
- 每条命运线 3 阶段，共 54 个阶段事件；
- 命运线阶段适配为现有 `GameEvent`；
- `RECORD_EVENT` 初始化命运线状态并推进 `turn`；
- `APPLY_NARRATIVE` 写入八轴、标签、记忆、称号、伤疤和命运线状态；
- 第三阶段根据选择标签与 `threadAction` 落定为 resolved 或 broken。

### **类型接入**

- 使用 `types/game.ts` 已有 `NarrativeAxis`、`NarrativeTag`、`FateThreadState`、`ChoiceMemory`、`NarrativeState`、`EndingSummary`；
- 修正 `fate-threads.json` 中超出既有叙事轴的 `detachment`，改为 `freedom`。

### **展示**

- 事件卡显示命运线、阶段与进度点；
- 状态面板显示主轴、已落定/悬而未决数量；
- 结局页显示组合结局、命运线结果、关键记忆、墓志铭和签名。

## **四、下一步建议**

### **P0**

1. 年度/阶段 tick 与年度重心。
2. 结构化关系系统。
3. 事件池条件接入叙事轴与关系。

### **P1**

4. 完整生平时间线与跨局存档。
5. 纹理/称号系统与组合结局谱系。
6. 结局分享卡。

### **P2**

7. 同世代/同宗门对照。
8. 每日主题或世界事件。
9. 多周目收集与社区分享。

## **五、结论**

1in8b 值得重构的不是“随机事件数量”，而是：

- **把选择变成跨事件状态**；
- **把状态变成可解释结局**；
- **把结局变成可重玩的记忆**。

本轮 fanren-wiki 已完成第一层：**18 条命运线真正进入运行逻辑、选择记忆、结局与总结展示**。下一阶段的关键是把“事件按钮”继续升级为“年度生命循环 + 关系网络 + 可保存生平”。
