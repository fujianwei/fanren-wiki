# 索引

## 聚簇索引 vs 非聚簇索引

```
聚簇索引（主键索引）：
  叶子节点存的是完整行数据
  一张表只能有一个（数据按主键物理排序）
  
  主键 → 叶子节点 → 完整数据行

非聚簇索引（二级索引）：
  叶子节点存的是主键值，不是完整数据
  
  普通索引 → 叶子节点 → 主键值 → 再查聚簇索引 → 完整数据行
  这个过程叫：回表
```

**回表的代价：** 一次普通索引查询 = 两次 B+ 树查找，性能比主键查询低。

---

## 覆盖索引（避免回表）

```
查询的字段全部在索引里，不需要回表：

索引：(name, age)
查询：SELECT name, age FROM user WHERE name = '张三'

→ 索引叶子节点已有 name 和 age
→ 不需要回表
→ 覆盖索引，性能高
```

EXPLAIN 里 Extra 列显示 `Using index` = 命中覆盖索引。

## 联合索引与最左前缀

```
索引：(a, b, c)

能走索引：
  WHERE a = 1
  WHERE a = 1 AND b = 2
  WHERE a = 1 AND b = 2 AND c = 3
  WHERE a = 1 AND b > 2     ← a 走索引，b 范围后 c 失效

不能走索引：
  WHERE b = 2               ← 跳过了 a
  WHERE c = 3               ← 跳过了 a, b
  WHERE b = 2 AND c = 3     ← 跳过了 a
```

记忆口诀：从左到右，中间不能断，范围之后失效。

## 索引失效的常见场景

```
1. 对索引列做函数操作
   WHERE YEAR(create_time) = 2024  ← 失效
   改为：WHERE create_time >= '2024-01-01' AND create_time < '2025-01-01'

2. 隐式类型转换
   索引列是 varchar，WHERE id = 123（数字）← MySQL 自动转换，失效

3. 用了 != 或 NOT IN
   WHERE status != 1  ← 一般失效（走全表扫描更快）

4. LIKE 左模糊
   WHERE name LIKE '%张'  ← 失效
   WHERE name LIKE '张%'  ← 可以走索引

5. OR 连接非索引列
   WHERE a = 1 OR b = 2  ← 如果 b 没索引，全表扫描
   原因：OR 语义是满足任意一个即可，b 没索引必须全表扫才能找到所有 b=2 的行
```

## AND vs OR 对索引的影响

```
AND 连接（a 有索引，b 无索引）：
  WHERE a = 1 AND b = 2
  → a 的索引生效，先定位 a=1 的行
  → 在结果集上再过滤 b=2
  → 索引有效，只是 b 做额外筛选

OR 连接（a 有索引，b 无索引）：
  WHERE a = 1 OR b = 2
  → 必须找到所有 a=1 的行 + 所有 b=2 的行
  → b 没索引，只能全表扫描
  → 索引失效，全表扫描
```

AND = 缩小范围，索引可以用；OR = 扩大范围，有一个没索引就全表。
