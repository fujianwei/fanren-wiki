## 匿名内部类与 Lambda

**匿名内部类的使用流程：**

```java
// 第一步：定义接口（只声明，不实现）
public interface RejectedExecutionHandler {
    void rejectedExecution(Runnable r, ThreadPoolExecutor executor);
}

// 第二步：某个类持有这个接口类型的字段，并提供 set 方法
public class ThreadPoolExecutor {
    private RejectedExecutionHandler handler;

    public void setRejectedExecutionHandler(RejectedExecutionHandler handler) {
        this.handler = handler;
    }

    // 需要时调用
    private void reject(Runnable command) {
        handler.rejectedExecution(command, this);
    }
}

// 第三步：使用时传入实现（匿名内部类或 Lambda）
executor.setRejectedExecutionHandler(new RejectedExecutionHandler() {
    public void rejectedExecution(Runnable task, ThreadPoolExecutor executor) {
        log.warn("任务被拒绝：{}", task);
    }
});
```

本质是**把行为作为参数传递**，让调用方决定具体逻辑。

**匿名内部类 vs 普通类：**
```java
// 普通类：先定义，再使用，有名字，可复用
public class MyHandler implements RejectedExecutionHandler { ... }
executor.setRejectedExecutionHandler(new MyHandler());

// 匿名内部类：定义和使用合并，没有名字，只用一次
executor.setRejectedExecutionHandler(new RejectedExecutionHandler() { ... });
```

## Lambda 表达式

Lambda 是匿名内部类的简写，前提是接口只有一个抽象方法（函数式接口）。

**完整写法（匿名内部类）：**
```java
executor.setRejectedExecutionHandler(new RejectedExecutionHandler() {
    @Override
    public void rejectedExecution(Runnable task, ThreadPoolExecutor executor) {
        log.warn("任务被拒绝：{}", task);
    }
});
```

**Lambda 简写：**
```java
executor.setRejectedExecutionHandler((task, executor) -> {
    log.warn("任务被拒绝：{}", task);
});
```

两者完全等价，Lambda 省略了接口名和方法名，只保留参数和方法体。编译器能自动推断出你实现的是哪个方法。

## 入参传接口（策略模式）

方法入参是接口而不是具体类，调用方自己决定实现：

```java
// 入参是接口
setRejectedExecutionHandler(RejectedExecutionHandler handler)

// 传具体类：行为固定
// 传接口：  行为可扩展，调用方决定怎么实现
```

这是**策略模式**的核心——解耦"触发时机"和"处理逻辑"：
```
线程池只定义"拒绝时调用 rejectedExecution"
具体怎么处理，由外部传入的实现决定
```

Java 里常见的入参传接口：
```java
Comparator     → Collections.sort(list, comparator)
Runnable       → new Thread(runnable)
RejectedExecutionHandler → executor.setRejectedExecutionHandler(handler)
```

都是**面向接口编程**的典型应用：定义规范，行为由调用方决定。
