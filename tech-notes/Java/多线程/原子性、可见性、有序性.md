# 原子性、可见性、有序性

并发编程要解决的三个核心问题。

---

## 原子性

**操作不可被中断，要么全做要么不做。**

```
count++ 看起来是一步，实际是三步：
1. 读取 count 的值
2. 计算 count + 1
3. 把结果写回 count

线程A 执行到第2步，线程B 也来读 count
→ 两个线程都读到旧值，各自加1写回
→ 最终结果少加了一次
```

类比：银行转账，扣款和入账必须同时成功或同时失败，不能只扣款没入账。

---

## 可见性

**一个线程修改了变量，其他线程能立即看到。**

现代 CPU 有多级缓存（L1/L2/L3），线程修改变量先写到 CPU 缓存，不会立即写回主内存：

```
线程A（CPU1）    主内存      线程B（CPU2）
count=0  ←───  count=0  ───→  count=0

线程A：count=1（只改了CPU1缓存）
               count=0（主内存还是0）
线程B：读到 count=0  ← 看不到线程A的修改
```

volatile 解决可见性：强制写回主内存，强制从主内存读。

---

## 有序性

**代码执行顺序和编写顺序一致。**

JVM 和 CPU 会对指令重排序来优化性能，单线程下没问题，多线程下会出错：

```java
// 双重检查锁（DCL）单例
if (instance == null) {
    synchronized (this) {
        if (instance == null) {
            instance = new Object(); // 这行会被重排！
        }
    }
}

// new Object() 实际分三步：
// 1. 分配内存
// 2. 初始化对象
// 3. 把引用指向内存地址

// 重排后可能变成：1 → 3 → 2
// 线程B 看到 instance 不为 null（第3步完成）
// 但对象还没初始化（第2步没完成）
// 线程B 使用了未初始化的对象 → 出错
```

解决：给 instance 加 volatile，禁止重排序。

---

## 三者与各并发工具的关系

| | 原子性 | 可见性 | 有序性 |
|------|------|------|------|
| synchronized | ✅ | ✅ | ✅ |
| volatile | ❌ | ✅ | ✅ |
| CAS/原子类 | ✅ | ❌ | ❌ |
| ReentrantLock | ✅ | ✅ | ✅ |

```
需要全部保证    → synchronized 或 ReentrantLock
只需可见性/有序性 → volatile
只需原子操作    → AtomicInteger 等原子类
```
