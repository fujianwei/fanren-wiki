# Redis 高可用

三种方案，复杂度递增：**主从复制 → 哨兵 → Cluster**

---

## 主从复制

一个主节点（Master）+ 多个从节点（Slave），主节点负责读写，从节点只读，数据自动同步。

```
写请求 → Master
              ↓ 同步数据
         Slave1  Slave2  Slave3
读请求 → 任意 Slave（读写分离，分担压力）
```

**同步原理：**
```
第一次连接（全量同步）：
Master 执行 BGSAVE 生成 RDB → 发给 Slave → Slave 加载
期间新产生的写命令记录在 repl_backlog 缓冲区
RDB 加载完后，把缓冲区命令也发给 Slave

后续（增量同步）：
Master 每执行一条写命令，同步发给所有 Slave
通过内存中的 repl_backlog 缓冲区传输，不落盘
```

注：全量同步用 RDB（磁盘文件），增量同步用 repl_backlog（内存缓冲区），两者存的都是写命令，但用途不同——AOF 是持久化到磁盘用于重启恢复，repl_backlog 只用于主从同步。

**问题：主节点挂了需要人工切换，期间服务不可用。**

---

## 哨兵（Sentinel）

在主从基础上引入哨兵节点，自动监控主从状态，主节点挂了自动完成故障转移。

**怎么判断 Master 挂了：**
```
哨兵每隔1秒给 Master 发心跳（PING）
Master 没有回应
→ 单个哨兵认为主观下线（可能是网络抖动）
→ 通知其他哨兵确认
→ 超过半数哨兵都认为挂了 → 确认客观下线
→ 开始故障转移
```
超过半数确认是为了防止网络抖动误判。

**故障转移过程：**
```
1. 哨兵们投票选出领头哨兵负责本次切换
2. 从 Slave 中选一个升为新 Master
   （优先级高的、数据最新的、id最小的）
3. 通知其他 Slave 指向新 Master
4. 通知客户端新 Master 地址
5. 原 Master 恢复后降级为 Slave
```

**问题：单主节点有容量和写性能上限，数据量大时撑不住。**

---

## Cluster（集群）

本质是**多组「主从+哨兵」的组合**，每组负责一部分数据：
```
Master1+Slave1（负责 slot 0~5460）
Master2+Slave2（负责 slot 5461~10922）
Master3+Slave3（负责 slot 10923~16383）
```
每组内部有主从同步和自动故障转移，组和组之间负责不同的数据分片。

数据分片存储在多个主节点，每个主节点负责一部分数据，同时有自己的从节点。

**数据分片原理（slot）：**
```
Redis Cluster 把所有数据分成 16384 个槽（slot）
key → CRC16(key) % 16384 → slot 编号 → 对应节点

Master1 负责 slot 0 ~ 5460
Master2 负责 slot 5461 ~ 10922
Master3 负责 slot 10923 ~ 16383
```

为什么是 16384 个 slot？16384 用 2KB 就能在心跳包里表示，够用且不浪费。

**请求路由：**
```
GET user:1 → 计算 slot=5000 → 在 Master1
连的不是 Master1 → 收到 MOVED 重定向 → 重新连 Master1
```

**扩容：**
```
加入新节点 Master4
从 Master1、2、3 各迁移一部分 slot 给 Master4
迁移过程不中断服务
```

**key 与节点的关系：**
```
单个 key：只能落在一个节点上
  user:1 → slot 5000 → Master1，永远只在 Master1

多个 key：可以落在不同节点上
  user:1  → slot 5000  → Master1
  order:1 → slot 8000  → Master2
  item:1  → slot 12000 → Master3
```

**故障转移：每个 Master 有自己的 Slave，Master 挂了 Slave 自动升主，其他节点不受影响。**

---

## 三种方案对比

| | 主从复制 | 哨兵 | Cluster |
|------|------|------|------|
| 故障自动转移 | ❌ 需人工 | ✅ 自动 | ✅ 自动 |
| 水平扩展 | ❌ | ❌ | ✅ |
| 复杂度 | 低 | 中 | 高 |
| 适用场景 | 读多写少，数据量小 | 需高可用，数据量不大 | 数据量大，高并发写 |

**演进关系：**
```
主从复制：有备份，但故障需人工处理
    ↓
哨兵：自动故障转移，但单主节点有容量上限
    ↓
Cluster：容量和写能力水平扩展，彻底解决单点瓶颈
```
