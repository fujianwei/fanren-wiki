# Redis 持久化

## 什么是持久化

Redis 基于内存操作，断电或重启后内存数据全部消失。持久化就是把内存数据**额外备份一份到磁盘**，重启后可从磁盘恢复。

```
正常运行：所有读写操作都在内存，速度极快
持久化：  异步把内存数据写一份到磁盘，不影响主流程
重启恢复：从磁盘文件把数据重新加载回内存
```

不开持久化：Redis 重启后数据全没，只能当纯缓存用。
开了持久化：Redis 重启后从文件恢复，数据还在。

## RDB（快照）

某一时刻将内存的**全量数据**序列化压缩，写入 `.rdb` 文件。类比：**给内存拍了一张照片**。

```
内存数据：
  key1 -> "abc"
  key2 -> 123
  key3 -> [1,2,3]

↓ BGSAVE

dump.rdb：把以上所有数据序列化压缩写入磁盘
```

**触发方式：**
- 手动：`SAVE`（阻塞主线程）/ `BGSAVE`（fork 子进程，不阻塞）
- 自动：配置触发条件，如 900 秒内有 1 次写操作

**BGSAVE 原理：**
fork 子进程写磁盘，主进程继续处理请求，利用 COW（写时复制）。

**COW（写时复制）：**
fork 后父子进程共享同一份内存页。子进程只读内存数据做持久化，不会修改内存。只有父进程（主进程）处理写请求时才触发 COW——复制被修改的内存页，子进程始终读 fork 那一刻的原始数据：

```
fork 后，父进程无写操作：
主进程 ──┐
         ├──> 共享同一份内存页
子进程 ──┘
           ↓
       子进程直接读共享内存页，序列化写入磁盘，零额外内存开销

fork 后，父进程有写操作：
主进程 ──> 修改 key1 → 触发 COW，复制 key1 所在内存页，在副本上修改
子进程 ──> 继续读原始内存页（快照数据不变）
```

COW 的本质：保护子进程看到的快照数据不被主进程写操作破坏，主进程写哪页就复制哪页。

**fork 的两个开销：**
1. **fork 瞬间**：需复制父进程页表（内存地址映射），数据量越大页表越大，fork 耗时越长，主线程短暂阻塞
2. **fork 之后**：父进程写操作越多，COW 触发越多，内存占用膨胀越大，极端情况接近翻倍

所以 BGSAVE 最好在**低峰期**触发，写操作少，COW 触发少，内存开销小。

**优点：**
- 文件紧凑，体积小，恢复速度快（直接加载数据，不用重放命令）

**缺点：**
- 两次快照之间的数据会丢失（如每 900 秒一次，宕机可能丢近 900 秒数据）
- fork 子进程有开销，数据量大时 fork 耗时明显，期间大量写操作会触发 COW，内存占用可能接近翻倍

## AOF（追加日志）

记录每一条**写命令**，而不是数据本身。类比：**流水账**。

```
每次写操作 → 追加一条命令到 .aof 文件

SET key1 "abc"
SET key2 123
INCR key2
DEL key1
...
```

恢复时把 .aof 文件里的命令从头到尾重放一遍，内存数据恢复。

**三种刷盘策略：**

| 策略 | 说明 | 数据安全性 | 性能 |
|------|------|------|------|
| always | 每次写命令立即刷盘 | 最安全，不丢数据 | 最差 |
| everysec | 每秒刷盘一次 | 最多丢 1 秒数据 | 较好 |
| no | 由 OS 决定刷盘时机 | 不可控 | 最好 |

生产环境一般用 `everysec`，平衡安全性和性能。

**AOF 重写：**
命令只追加不删除，文件会越来越大，存在大量冗余：
```
SET k 1
SET k 2
SET k 3   ← 前两条没用了，最终结果只是 k=3
```
重写后合并为：`SET k 3`，文件体积大幅缩小，数据等价。

**优点：**
- 数据丢失少，最多丢 1 秒

**缺点：**
- 文件体积大，恢复时需重放所有命令，速度慢

---

## 混合持久化（4.0+）

AOF 重写时，先写 RDB 全量快照，再追加增量 AOF 日志，兼顾两者优点。

```
[RDB 全量快照] + [增量 AOF 日志]
```

恢复时先加载 RDB（快），再重放少量增量 AOF（数据完整），生产环境推荐使用。

---

## 对比总结

```
RDB：存数据快照，像"照片"，恢复快，可能丢数据
AOF：存操作日志，像"流水账"，恢复慢，数据更完整
混合：RDB + 增量AOF，兼顾速度和完整性
```

| | RDB | AOF | 混合 |
|------|------|------|------|
| 文件内容 | 全量数据快照 | 写命令日志 | RDB + 增量AOF |
| 恢复速度 | 快 | 慢 | 较快 |
| 数据丢失 | 多（取决于快照频率） | 少（最多1秒） | 少 |
| 文件体积 | 小 | 大 | 中 |
| 生产推荐 | 一般不单独用 | everysec | ✅ 推荐 |
